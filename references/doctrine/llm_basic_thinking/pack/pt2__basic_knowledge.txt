1. Law of Dominant Trends (Multi-Timeframe Alignment)

Law: Higher timeframe defines allowed direction. Lower timeframe only times entry. LTF never votes on side against HTF.

How the long-term tide controls short-term timing

│                        │               │ permission                  │                 │

Exact control chain

1. Classify tide: price vs HTF structure (e.g. above BB mid / above envelope of SMA(high)/SMA(low) / both CCI > SMA on HTF / close > HTF EMA).
2. Hard filter: if tide = long → discard all short LTF setups; if short → discard all longs; if flat / conflict → no trade.
3. Slingshot only with the tide: on LTF, wait for against-the-entry micro move that does not break HTF structure (pullback into ribbon, fast CCI below its SMA while slow still above, RSI into lower band while price still above HTF BB, etc.).
4. Fire only when LTF resumes with HTF: reclaim / cross / close back outside envelope on the HTF side.
5. Kill if tide breaks: HTF close wrong side of regime line → flatten; no averaging against gravity.

One sentence:
HTF is the binary gate on side; LTF only chooses when within that gate — pullback = load the slingshot; resume with HTF = release.

Lab examples: dual CCI same side on second TF; BB on M5+M30+H1 then RSI entry on M5; shifted envelope M5 regime then M1 outside envelope; SNAP-8 M5 EMA50 then M1 8/21 + RSI.

3. Environmental Survival (Regime Detection)

Mandate: Environment is a state machine. Strategy set is a function of state. Wrong playbook in new state = account damage.

Strict process (objective)

1. Measure, don’t feel — fixed features every bar/session:
   • Direction: HTF slope / side of mid / envelope side
   • Range vs trend: ADX or |close−mid|/ATR, HH/HL vs LH/LL structure
   • Volatility: ATR%ile vs lookback
   • Efficiency: net move / path length (choppy vs clean)
   • Session / news flags if in rules

2. Map to discrete regime — bull / bear / chop (and your finer 14+1 labels when codified: e.g. strong trend, weak trend, range, breakout, post-news, dead session, etc.).

3. Confirm shift — regime change only when:
   • HTF structure flips and
   • Hold for N HTF bars or a close beyond invalidation level and
   • Optional: volatility regime change (ATR band jump).

4. Capital Preservation Mandate (Risk & Sizing)

Highest mandate: never breach max daily loss (and max DD). Edge is optional; survival is not.

Math (per trade)

  Risk$ = E × r_(base) × m_(conf) × m_(regime)

  Size = Risk$/(StopDistance in $ per unit)

• E = equity (or challenge balance)
• r_(base) = base risk fraction (e.g. 0.25–0.5% scalp; challenge often ≤0.5–1% hard cap)
• m_(conf) = confidence multiplier ≤ 1…m_(max)
• m_(regime) = environment multiplier (chop ≪ trend)

Scale up only when all true (high confidence)

• HTF + LTF aligned (Law 1)
• Momentum/launch or clean pullback signature (Law 2) matches playbook
• Regime allows that playbook (Law 3)
• Spread/ATR acceptable
• Daily loss budget remaining

Then m_(conf) may rise (e.g. 1.0 → 1.25 → 1.5) only inside a hard ceiling so
Risk$ ≤ R_(max_trade) and projected loss if SL hit still fits daily budget.

Scale down / zero under uncertainty

• HTF flat or conflict → m = 0 or min micro
• Chop regime → m ≪ 1 or flat
• After loss streak / approaching daily cap → m collapses

Daily loss hard gate

  RemainingDaily = L_(day) − RealizedLoss_(today) − OpenRisk

• New trade only if Risk$ ≤ RemainingDaily
• If RealizedLoss ≥ L_(day) → flat rest of day (no “get it back”)
• Open risk counts: no stacking that could breach L_(day) if all stops hit

Prop-style: max daily, max total DD, and often max per-trade are hard stops on the system, not guidelines. Size is the only continuous control that guarantees those bounds.

Mathematical separation

1. Two periods on same series:
   • vₜ = f(price; P_(fast)) e.g. CCI(30), RSI(7), EMA(8)
   • Fₜ = f(price; P_(slow)) e.g. CCI(100), EMA(21)/BB(100), HTF SMA envelope

2. Two timeframes:
   • Velocity lives on LTF
   • Force is HTF state projected onto LTF (align HTF bar → N LTF bars) — weight is not re-estimated every M1 tick as if it were M1 noise

3. Shifted / envelope structure (your king family):
   • Force ≈ price vs SMA(high) and SMA(low) on M5 (must clear both → full body of mass outside band)
   • Speed ≈ same test on M1 for trigger
   • Implementation note: lab uses trailing SMA(period), not future-leaking plot shift

4. Slingshot identity:
   • Force with tide (F bull)
   • Velocity temporarily against (v dips) → breath
   • Velocity re-aligns with force → entry
   • If force flips, velocity signals are invalid regardless of how fast they look

One sentence:
Velocity answers “how fast is this bar’s move?”; force answers “which way is the market’s mass leaning?” — only trade when velocity is used inside force, never when fast noise is treated as the trend.

3. Volatility Compression as Phase Boundary (fractional Bollinger)

Fractional boundary

  m = SMA(C; N), N=100
  σ = stdev(C; N)
  U = m + d⋅σ, L = m − d⋅σ, d = 0.5

d=0.5 is ultra-tight vs classic d=2. The “tube” is a phase boundary: small distance from mean counts as escape.

Escape velocity (redefined)

Under d=2, escape = rare 2σ event.
Under d=0.5:

  escape velocity achieved ⟺ C > U_(0.5) = m + 0.5σ

(or C < L_(0.5)).
So “escape” means: persistent mild expansion beyond a thin shell, not a statistical outlier.

4. Vector Efficiency and Entropy Masking (chop kill-switch)

Premise: G aligned is necessary, not sufficient. High-entropy micro path produces false velocity triggers.

Efficiency ratio (Kaufman-style; already in lab feature code)

Over window W (e.g. 10–14 bars on LTF):

  E = (lvert Cₜ − C_(t−W)rvert)/(∑ᵢ₌₀^(W−1)lvert Cₜ₋ᵢ−Cₜ₋ᵢ₋₁rvert)

• E → 1: straight vector (low entropy)
• E → 0: path cancels (high entropy / chop)

Mask (example hard gate used in doctrine tests):

  allow triggers ⟺ E ≥ θ_E,  θ_E ≈ 0.35

else force signal = 0 even if oscillators scream.

Directional dominance (ADX-class)

  allow ⟺ ADX(P) > θ_(ADX),  θ_(ADX) ≈ 25

ADX is smoothed |+DI − −DI| dominance — low ADX = no directional mass in the DI field.

Combined paralysis rule

  Executable = [G ≠ 0] ∧ [E ≥ 0.35 ∨ ADX>25] ∧ [setup topology]

Practical AND of efficiency and ADX is stricter; OR is looser. Prop-safe default: AND, or ADX primary + E secondary.

What gets masked: any LTF momentum/slingshot predicate (CCI crosses, micro envelope breaks, RSI snaps) while entropy high — those are false-positive velocity under broken local vector efficiency.

Note: core hunter entries do not all hard-code ADX yet; this gate is the correct mechanical mask when micro-entropy is the failure mode.
